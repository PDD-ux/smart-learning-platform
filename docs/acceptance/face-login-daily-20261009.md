2026-10-09，桌面主仓库、本地 Next.js 与 PostgreSQL。用户确认“学习者人脸登录自动打卡，密码登录后手动打卡”；本轮只执行 §19。

已实现登录方式切换、独立授权版本 `face-login-attendance-v2`、模板录入/重录/删除、工作台每日状态和一键普通打卡。普通方式直接完成，不再进入审批；不增加学习时长、连续天数、XP 或计划完成状态。管理员继续使用密码登录，只读统计人脸核验、普通打卡、历史待确认。

数据库迁移新增 `SELF_CHECK_IN`、可空 `checkInDay`、用户/日期唯一约束和一次性挑战摘要表。旧记录保留，不追溯伪造日期。写入先锁定当前用户，在数据库内保留首次成功方式和时间；人脸会话签发前锁定并复核账号角色、模板ID/更新时间/授权及挑战期限。账号绑定的HMAC挑战两分钟有效，数据库原子消费一次，失败不能重放。

本地真实 HTTP/数据库通过：密码登录产生0条打卡；5个并发普通打卡请求全部200且仅一条记录、首次时间一致；管理员403、匿名401；管理员普通打卡筛选、总数分项一致。证据为 [JSON](face-login-daily-20261009.json)。临时账号与关联记录已清理。

浏览器通过：人脸服务未配置时提示使用密码，不申请摄像头；隔离账号密码登录后显示尚未打卡，点击后显示普通打卡且按钮禁用；工作台刷新保留状态、设置入口可达，独立授权区域默认折叠。后续其他页面切换了浏览器共享身份，网络请求仅比较是否属于临时账号确认已切换，未对新账号继续打卡或登出；设置页的未打卡属于该另一账号，不作同一账号回读证据。保存 [工作台截图](screenshots/daily-checkin-dashboard-20261009.png) 和 [人脸未接入提示](screenshots/face-login-unavailable-20261009.png)，临时测试页已关闭，保留用户原有页面。

## 明确阻塞

本机 `FACE_VERIFICATION_PROVIDER`、`FACE_INFER_URL`、`FACE_INFER_MODEL_VERSION`、`FACE_CHALLENGE_SECRET`、两套独立加密密钥及其ID均未配置；配置证据仅保存存在性布尔值。真实 `/api/auth/face/challenge` 返回503 / `FACE_SERVICE_UNAVAILABLE`。没有向任何远端发送用户人脸、没有执行真实录入或真实活体验证，也没有伪造人脸登录成功。已有 Ascend OCR/课堂分类服务不等于人脸特征和活体服务。

要解除阻塞，需要已获授权的人脸服务实现 `POST /v1/face/enroll` 和 `POST /v1/face/verify`，返回实际单人检测、特征、模型版本及匹配/活体结论；验证请求含按顺序连续动作画面（最多12张）、服务端解密模板、挑战ID与动作。生产地址必须HTTPS，调用15秒超时，凭据/独立随机密钥仅配置到服务端环境。配置后由学习者密码登录、独立授权重新录入，再在登录页实际完成随机动作，核对会话、今日记录与管理员分类，另测不匹配/多人/静态照片/重放拒绝，方可标记真实人脸验收通过。

## 可复现入口

1. 桌面主仓库执行 `npx prisma migrate deploy`、`npx prisma generate`（Windows需先释放本仓库占用Prisma DLL的Web进程），启动 `npm run dev`。
2. 执行 `npx tsx scripts/acceptance/face-login-daily.ts`：自动创建隔离账号，真实登录/并发打卡/权限/管理统计/配置检查，结束自动清理，不打印密码或token。
3. 浏览器验收可加 `--keep-ui`，仅在ignored目录保留短期测试凭据；结束执行同入口 `--cleanup-ui`。不使用已有用户作为写测试对象。
4. 认证/摄像头回归：`npx vitest run tests/unit/api/face-login.test.ts tests/e2e/face-login-panel.test.tsx`。全量回归517/517通过；TypeScript与Lint通过，Lint仅既有字体/img警告。生产构建结果见PROGRESS。
