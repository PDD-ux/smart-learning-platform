桌面主仓库本机演示，独立CPU真实模型，非mock，不改现有Ascend课堂推理。官方固定YuNet/SFace权重按Git LFS SHA256验证，MediaPipe Face Landmarker v1按台账验证；依赖/模型/许可和命令见[服务说明](../../services/face-infer/README.md)。本地服务8002与网页3000保持运行，凭据仅在被忽略.env.local。

## 已通过

- [13项真实模型公共样本](face-real-models-20261009.json)：单人录入、128维归一化、同人匹配；三种动作静态图均拒绝；不同人/多人/无人脸/坏模板拒绝。样本来自Google官方公开测试素材，来源URL/SHA256在证据，不包含用户照片、向量或分值。
- [11项真实HTTP/PostgreSQL](face-real-product-20261009.json)：未经同意拒绝、真实模型录入、密文模板和私有加密照片、静态/不同人拒绝且无登录会话/打卡、挑战重放拒绝、删除模板和照片。仅使用隔离账号与公共图片，全部临时账号/模板/私有照片已清理。
- [服务边界](face-service-boundary-20261009.json)：缺Bearer401、错误输入422、超大请求413、错误不回显输入。服务禁用HTTP访问日志，无照片/向量/分值输出。
- 合成动作策略规则单测通过（17条断言，非真实摄像头）；32项相关TS回归、type-check、改动TS的ESLint通过。首次type-check撞上Next重启清理生成类型文件，稳定后重检通过。未再生产构建以保持演示服务。
- 浏览器确认登录人脸入口、说明和未填账号禁用；账号自动填充清空后才保存[不含个人信息截图](screenshots/face-real-login-20261009.png)。保留用户原登录页，不开启摄像头或勾本人授权。

## 修复和诊断

首次OpenCV加载ONNX失败：原生Windows加载器无法可靠读取中文项目路径。改用Python读取、固定hash校验后的内存buffer传入OpenCV和MediaPipe，重启后模型健康检查成功。Windows虚拟环境启动器PID与实际解释器不同：stop最初安全拒绝，修正为先比对本次随机instanceId再停止健康检查返回的实际PID；stop/start复验通过。

产品脚本首次错误地预期重放400，实际规范安全路径统一401；修正验收断言后完整通过，没有放宽认证。错误输入的模型返回固定422，Next未知模型服务故障仍关闭登录。

## 仍待本人验收

真实动态动作通过及成功人脸登录没有在本轮执行：证据明确userCameraTested=false、dynamicPositiveTested=false、successfulFaceLoginTested=false。公共照片匹配、静态拒绝及规则单测不等于本人全链路成功；基础动作检查无法保证专业防视频回放、深度伪造或客户端伪造，不能写成金融级活体。

1. 本人用密码登录，工作台进入“每日打卡与人脸登录设置”。
2. 展开可选人脸区，亲自阅读并同意录入授权，开启摄像头正视录入；旧模板版本不兼容需重录。
3. 退出后在登录页填写同一邮箱/手机号，切换人脸登录，开启预览并点击准备好了。
4. 点击验证后闭眼约1秒再睁眼，或按提示向自己的左/右侧小幅转头后回正，在约2.5秒采集内完成。
5. 成功应进入工作台并显示今日打卡；当天此前普通打卡会保留第一次方式/时间，不另建记录。随后核对删除模板即停用人脸登录。

本人操作才产生真实生物授权；实现工作不能替本人同意或用公共测试图片冒充本人录入。未通过时记录真实提示与所选动作，不能降低活体门槛绕过。

复现：`npm run face:setup`、`npm run face:start`、`npm run face:status`；配置后重启原Next；验收命令见服务README。`npm run face:stop`只停止本入口服务。部署密钥必须保留，不能提交、公开或擅自轮换。
