## 原因与修改

普通npm run demo:check -- --import实际将ASR判为blocked，而本机本地ASR已配置。local-demo静态导入Prisma运行时，使其先加载.env；main的Next加载随后把这些值当作已有进程环境，无法再采用.env.local。隔离真实子进程用合成.env/.env.local在原实现上复现check/start两个失败，继承环境优先测试通过。

scripts/demo/local-demo.ts改为静态type-only PrismaClient、databaseCheck中动态导入运行时；main先loadEnvConfig(root,true)，按Next开发模式加载，再进入预检。显式进程环境仍优先，.env.development.local > .env.local > .env.development > .env；不强制override、不改配置文件或签名密钥。启动Next开发子进程继承当前环境，已运行网页仍仅按品牌复用，不能据此断言其配置最新。

新增tests/unit/deployment/local-demo-env.test.ts：分别实际执行check/start、显式进程环境优先、开发专属local覆盖普通local。使用临时合成配置、数据库仅指向127.0.0.1:1的不可用测试地址，不连接学习库；没有模型、ASR订单、摄像头或真实SQL写入。临时目录按已验证的系统临时根及固定前缀清理。
