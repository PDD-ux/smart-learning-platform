## 发现与处理

1. 第一次问答 HTTP 503，但原接口只返回统一错误，无法区分上游失败和输出格式失败。增加与上游一致的 traceId 和脱敏错误码日志，不打印密钥、问题、回答或原始异常消息。
2. 随后的完整复跑曾成功；再次复跑问答又失败，日志明确为 SCHEMA_INVALID。原提示使用伪 JSON/占位符，改为合法 JSON 示例并明确引用数值、可选 blockIndex 不可为 null；问答与出题均降低 temperature 至 0.1。保持原来的两次结构化输出校验尝试，不无限重试，也不把错误格式强行修成答案。
3. 旧版一次出题将“减去梯度”和“加上负梯度”同时作为不同选项。提示补充严格只有一个正确答案、干扰项不能为同义表达/等价公式，并使用满足约束的合法题目示例。
4. 新增模型响应校验：单选选项 2–6 个、忽略首尾空白/大小写后不重复，标准答案必须逐字匹配一个选项；判断题和简答题没有选项，判断题标准答案必须是 true/false。兼容历史题目中文真假值和选项字母的既有作答判分不变。
5. 出题复跑也遇到 HTTP 503。独立真实诊断得到一份缺失 pointIndex 键闭合引号的无效 JSON，并且没有服从题目数，说明不能把模型返回当成稳定结构。最终提示明确成对引号、请求数量且不必覆盖每个知识点，同时为出题增加脱敏错误码与 traceId 日志。最终完整复跑通过。
