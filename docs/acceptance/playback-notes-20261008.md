# §15.1 已上传视频播放同步笔记验收

日期：2026-10-08。位置：桌面主仓库。用户确认方案：视频提前解析，播放时按已有时间引用展示重点。

## 实现

- 视频学习页右侧新增播放同步笔记；跟随播放/全部重点、可点击来源时间、当前转写原文、个人补充。
- 仅采用已有知识点的 video 引用，按秒排序，同时间合并，过滤重复/非视频/越界/非法时间。展示最近已到达的来源重点至下一来源；这是浏览区间，不代表精确语义章节边界。首个重点之前不展示未来重点。
- 当前转写只按真实 startMs/endMs 半开区间显示，空档明确提示。旧资料没有知识点时间引用时保留完整笔记和个人补充，不推测定位。
- 补充首次输入时冻结时间；保存写入既有 Note，失败保留草稿与时间，成功进入我的笔记。AI 笔记重新整理不触碰个人笔记。
- 接入 timeupdate、seeking、seeked、pause、loadedmetadata 和续播进度；理解任务进入终态后刷新产物。不引入播放时 AI 调用、直播、数据库迁移、接口或依赖。

## 验证

- 新增 6 项测试：时间引用分组和过滤、边界与向后跳转、跟随/全部/回看、补充失败重试与定位保留、无定位及转写空档、学习页播放器事件与个人笔记接入。
- 全量 Vitest 77 文件、450/450 通过。播放器页面替身测试有 React act 提示；真实浏览器检查 error/warn 为空。类型检查、Lint 与 Next.js 生产构建通过（保留既有字体/img/可选 Valkey 提示）。
- 真实本地浏览器 + PostgreSQL：使用独立临时账号，FFmpeg 合成 40 秒测试视频、人工知识点和人工转写；未调用 AI、ASR 或 Ascend，不能用本次结果代表视频解析精度。
- 播放 0:00 无未来重点；回看 0:05 显示第一重点和原文；切到 0:20 显示第二重点和原文；暂停不继续切换。0:05 开始写补充，0:20 保存后数据库 Note.ref.timestampSec=5，页面我的笔记可见；进度 positionSec=20.289829，刷新实际播放器恢复同位置且 paused=true。
- 默认窄窗口为单列；临时 1440×900 桌面断点验证视频与同步卡并排且无横向溢出，之后恢复原窗口尺寸。截图见下方。
- 测试账号、视频对象及关联知识点、转写、AI/个人笔记和进度已清理；既有资料没有重跑、补写引用或覆盖。

## 复现

1. 在主仓库启动 npm run dev；使用本人已解析、知识点含视频时间引用的资料进入学习页。
2. 在“全部重点”点击时间后切到跟随播放；暂停或拖动时间轴，检查重点与当前转写；无时间引用应显示提示。
3. 写补充后继续播放或拖动，再保存；我的笔记时间应为首次输入时的位置，刷新后仍可见。失败时输入不丢失。
4. 如需隔离测试，在临时环境变量 UI_ACCEPTANCE_PASSWORD 设置至少 12 字符密码，运行 `npx tsx scripts/acceptance/playback-fixture.ts setup <独立runId>`，使用输出的临时账号登录。运行 verify 回读，再执行 cleanup 清理；测试数据明确为人工，严禁写成真实 AI 产物。移除临时密码环境变量。

## 限制

需要先有可靠的解析产物与时间引用；本轮未修复或重新验收既有长视频/ASR/Ascend 阻塞。实时展示的是预先解析重点，并非即时语音识别或现场生成笔记。没有引用的旧知识点不能自动同步；完整 AI 笔记仍可浏览。
