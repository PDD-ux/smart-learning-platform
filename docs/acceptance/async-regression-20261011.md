# §22.2 工作台与学习计划异步回归稳定性

2026-10-11 21:50完成。用户在§22.1留下两个并行回归问题后确认“下一步”，本轮只处理这两个测试的响应等待与隔离，不修改产品功能。先在TASKS明确编号和范围；本项属于已有加载/真实零值及计划操作验收，没有新增业务需求。

## 原因与修复

工作台的掌握度、账号统计和各份资料笔记独立异步读取。旧测试只等到0%掌握度就直接断言笔记和XP都是0；笔记还依赖资料列表完成后的多次读取，一个统计返回不代表其它统计完成。

`tests/e2e/dashboard-states.test.tsx`现在用受控Promise让掌握度先返回，账号统计及两份笔记逐项返回：先核对未完成的统计仍为“—”，账号返回后只把XP显示为0，首份笔记完成后仍不显示部分总数，全部笔记完成才显示0。保留真实0%与暂无记录的区分、独立重试和卸载旧响应保护。

计划创建结束会先增加列表revision，再由effect清除旧列表并重新读取。旧测试等到旧“标记完成”按钮可用之后，等待工具还可能让出执行权，刷新正好把该按钮移除；接口被调用或旧按钮启用不是刷新完成的信号。此前失败堆栈在等待之后的点击处，DOM确实处于“正在加载计划”。

`tests/e2e/plans-bank.test.tsx`分别控制创建响应、重新查询列表、完成响应；创建在途时按钮禁用，写成功而列表未返回时显示加载状态、没有可点击的完成按钮且没有自动调用完成接口。明确返回新标题“预习”的列表后，才重新查找并点击完成按钮；只提交一次，返回后核对“撤销完成”和1/1汇总。完整保留关联资料、目标分钟、学习/提醒本地时间转ISO的请求断言。beforeEach从clearAllMocks改为resetAllMocks，再设置本例默认值，防止未消费的一次性响应或旧实现进入下例。

没有增加固定睡眠、扩大测试超时、自动重试、串行配置或删除断言；没有修改vitest全局设置、生产页面、接口、字段、模型配置或依赖。
