# §26.10 题库生成失败诊断与质量保护 · 2026-10-16 09:24

用户截图为“AI生成题目未通过质量校验、本批未保存”，随后要求下一步。本轮只处理现有出题链路，不新增试卷导入，不切换百炼/新型号，不关闭质量校验或向原题库硬写演示题。

## 实现与安全契约

- 新增`src/lib/ai/schema-diagnostics.ts`，从Zod问题中只投影固定字段名、固定规则码、issue code和次数。未知字段名替换为`$`，不保留问题message、收到的值、任意params或完整模型输出；union分支有界遍历。AiError可带该结构，JSON解析失败改为固定提示，避免异常片段夹带模型内容。
- exercises/generate的503/AI_UNAVAILABLE保留，质量失败详情带traceId、requestedCount、failedQuestion、固定reason与安全diagnostic。前端沿用既有错误区显示固定中文分类，不再仅说“请重新生成”；日志同样不写原文/题干/选项/答案或原始异常message。原请求/成功DTO不变，无新表和迁移。
- 为选项缺内容、重复、答案范围/匹配、解析矛盾、判断题格式、重复题干、知识点/题型越界增加固定规则标签。既有整批原子保存不变，任何一道未通过均不保存前面已通过的题。
- 实际复验发现“表述错误，与规则不符”“表述混淆…规则不符”等元评价可以绕过原编号占位校验。新增对应拒绝模式和明确提示，保留混淆矩阵、错误处理、无逆映射等真实技术短答案；有限规则不等于自动识别全部语义错误。
- 模型可返回严格`{insufficientEvidence:true}`明确弃答。该弃答不自动重试，不保存之前题目，固定提示先核对资料/知识点、reason=INSUFFICIENT_EVIDENCE。带弃答标志又带题目的矛盾响应拒绝。模型仍可能不弃答，因此这不是语义正确性的保证。

## 真实受控结果：技术修复通过，当前资料5题质量未通过

从截图对应“映射与函数”资料只读复制6个知识点到随机临时学习者/内容中，不重跑视频、ASR、OCR，不改原资料归属/摘要/题库。两个完整请求均指定当前星火、5道单选，沿用每题最多2次格式校验请求；第二次在修复明确的元评价选项缺口后执行，未对同版本循环碰运气。

1. **诊断补齐后的首次请求**：真实HTTP200，31.483秒，返回/保存5题，仅临时账号。没有复现原截图那一次的具体拒绝，旧日志也无法恢复它，不能将本次结果伪称已找到原截图的确切失败项。人工核对本次题目仍不合格：存在不含具体事实的元评价选项；原知识点摘要把一般函数与一一对应混同，单射/满射相关表述存在混淆。HTTP200只说明结构和写入通过，不代表教学内容可靠。
2. **质量保护修复后的单次请求**：真实HTTP503，7.508秒，第1题两次均触发OPTION_CONTENT，新增题目0；页面可显示“选项缺少实际内容；本批题目未保存”，详情保留白名单诊断。模型仍未在这次请求主动弃答，故不能说弃答机制已经解决此资料问题。

两轮涉及的临时5题及全部临时用户/内容/知识点已清理。原有题库没有新写入或删除，原摘要不被悄悄改成“正确演示答案”。这不是用户需要导入试卷，也不能凭质量拒绝判断星火余额耗尽或NPU训练失败。

原视频知识点质量另列 **26.11**：须从实际时间引用核对转写/OCR与课堂语境，才能判断问题发生在来源识别还是摘要抽取，不能本轮直接归咎某个服务。本轮没有验收该15分钟视频的原始解析质量，也不宣称新题总体可用。
