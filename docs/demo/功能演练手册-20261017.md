## 3. 用户端演示动线（建议 12～15 分钟）

按左侧导航顺序走，每站给出「怎么点」和「讲什么」。

### 站点 1 · 我的学习 `/dashboard`
- **操作**：登录后默认落地页，展示学习总览、XP 等级、今日待办、资料卡片。
- **讲点**：学习档案与游戏化激励（XP / 连续天数），数据来自真实数据库而非写死。

### 站点 2 · 学习中心 `/import`
- **操作**：这里列出全部已导入资料（5 份）。点任一资料进入 `/study/[id]`。
- **讲点**：支持视频与文档两类；列表展示解析状态（已就绪 / 解析中 / 失败）。

### 站点 3 · 学习页 `/study/[id]`（核心，建议多停留）
- **操作**：
  1. 播放视频，右侧可看 AI 整理的重点；
  2. 播放过程中点「记笔记」保存一条笔记，随后点笔记可**按时间点回看**；
  3. 切到「知识点」「AI 笔记」标签查看已解析产物。
- **讲点**：ASR 语音转写 → 分段 → 大模型理解 → 知识点抽取的完整流水线；笔记与视频时间轴绑定（ContentRef 定位模型）。
- **注意**：页面上的「随播放 AI 整理」开关会消耗 API 额度，演示时建议**先关闭**，用已解析好的内容展示。

### 站点 4 · 我的笔记 `/notes`
- **操作**：查看全部笔记，用搜索框检索关键词，可导出 Markdown。
- **讲点**：笔记按资料聚合、支持全文检索与导出。

### 站点 5 · 练习题库 `/question-bank`
- **操作**：查看已有练习题，可以现场生成新题并作答，看判分与解析。
- **讲点**：做题结果回写掌握度（Mastery），驱动薄弱点分析。
- **注意**：生成题目依赖在线大模型，若现场网络或额度异常，展示已有题目即可。

### 站点 6 · 试卷中心 `/exams`
- **操作**：查看已生成的试卷列表 → 进入任一份 → 「开始考试」→ 逐题作答（可保存草稿）→ 交卷 → 查看成绩与解析。
- **讲点**：答卷一旦开始即**冻结题目快照**（不会因为题库改动而变化），交卷后客观题自动判分。

### 站点 7 · 组卷 `/exams/create`
- **操作**：选科目（行政职业能力测验）→ 设置题型与题量 → 提交 → 等待组卷完成 → 预览题目 → 确认生成试卷。
- **讲点**：组卷用**最大二分匹配**做选题，避免宽泛配额抢走限定配额的题目；题量不足时会明确提示「接受减量」，不允许把不足的草稿标记为完整卷。
- **注意**：这里生成的是**私人练习卷**，按设计不进入管理员阅卷流程（管理员阅卷见站点 16）。

### 站点 8 · 复习巩固 `/review`
- **操作**：先回忆 → 翻面核对 → 自评（0～3 档）→ 下一张。
- **讲点**：间隔重复算法，按自评结果调度下次复习时间。

### 站点 9 · 学习计划 `/study-plans`
- **操作**：新建一条计划（选资料 + 目标分钟 + 时间）→ 标记完成 → 可撤销/删除。
- **讲点**：计划与资料绑定，到期提醒。

### 站点 10 · AI 学习助手 `/assistant`
- **操作**：就当前资料提问，例如「帮我总结这份资料的重点」。
- **讲点**：Agent 会先判断意图（查进度 / 检索资料 / 出题 / 收尾），再决定动作。
- **重要（诚实表述）**：当前 `AGENT_REVIEW_READY=false`，助手处于**「证据模式」**——只依据资料原文摘录作答，不做自由发挥，因此遇到资料外的问题会回答得保守甚至只回原文。这是**刻意的安全设计**，不是故障；复跑忠实性验收后仍未达到开放标准，所以保持关闭。答辩时建议这样讲：「为了保证答案可溯源、不编造，当前默认走证据模式」。

### 站点 11 · 知识图谱 `/graph`
- **操作**：查看知识点图谱，点节点看关联与对应练习。
- **讲点**：知识点之间按前置 / 相关 / 举例关系建边，图谱由解析流水线自动生成。

### 站点 12 · 打卡设置 `/attendance`
- **操作**：查看今日打卡状态；若已录入人脸，可演示人脸打卡。
- **讲点**：端侧人脸推理（YuNet 检测 + SFace 比对），人脸特征加密存储，原始照片到期自动清理。
- **注意**：人脸服务必须先启动（准备步骤 3）。摄像头效果受现场光线影响，建议**提前录好并演练一次**；若现场不便，直接展示打卡记录页即可。

### 站点 13 · 课程讨论与消息（可选）
- **操作**：进入共享课程 → 发起提问 / 回复 → 在 `/messages` 看站内消息。
- **讲点**：讨论区带审核与举报闭环，处理结论会通过站内消息通知当事人。
- **注意**：该功能由 `DISCUSSION_RELEASE_READY` 总开关控制，演示前确认已为 `true`。

## 4. 管理员端演示动线（建议 8～10 分钟）

用 `demo-admin@wenhao.local` 登录后进入 `/admin`。

### 站点 14 · 管理总览 `/admin`
- **操作**：看平台关键指标（用户数、资料数、试卷数、签到等）。
- **讲点**：管理端与学员端共用一套鉴权，越权访问会被 403 拒绝（演练已验证：学员访问 `/api/admin/users` 返回 403）。

### 站点 15 · 用户管理 `/admin/users`
- **操作**：查看用户列表 → 新建用户 → 修改昵称 → 重置密码。
- **讲点**：密码 bcrypt(cost=12) 单向哈希，系统无法反查明文，只能重置。
- **注意**：接口支持修改昵称 / 密码 / 角色三项，**没有「禁用」字段**。

### 站点 16 · 科目与题库 `/admin/exam-bank`
- **操作**：查看科目「行政职业能力测验」→ 章节「判断推理」→ 9 道题目；可新建题目，走「创建 → 审核通过 → 启用」三步。
- **讲点**：题目**版本化**（每次修改产生新版本，已生成的试卷不受影响）；只有「已审核 + 已启用」的题才会进入组卷池；题源标注版权信息。
- **注意**：新建题目后**必须先审核再启用**，且章节也要先启用，否则会提示「章节不存在、已停用或不属于该科目」。

### 站点 17 · 试卷管理 `/admin/exam-papers`
- **操作**：新建试卷（选章节与题型配额）→ 预览选题结果 → 创建 → **发布**。
- **讲点**：发布前会重新校验题目快照完整性，防止题库变动导致试卷「缺题」。
- **注意**：发布共享课程只能选**该管理员本人名下已就绪**的资料；`demo-admin` 名下没有资料，这一步要么用有资料的账号演示，要么先导入一份。

### 站点 18 · 试卷批阅 `/admin/exam-attempts/[id]`
- **操作**：打开一份已提交的**正式卷**答卷 → 对主观题打分并写评语。
- **讲点**：客观题自动判分、主观题人工批阅；最终成绩一经评定即冻结，只允许在待批阅阶段反复留痕。

### 站点 19 · 共享课程 `/admin/courses`
- **操作**：查看已有共享课程；可准备并发布新课程。
- **讲点**：共享时可选择携带哪些内容（转写 / 文本块 / 知识点 / AI 笔记），并要求确认版权声明。

### 站点 20 · 讨论与举报 `/admin/discussions`
- **操作**：查看讨论列表与举报列表，处理一条举报（隐藏 / 驳回），填写处理结论。
- **讲点**：举报处理全程留审计日志，结论通知举报人。

### 站点 21 · 签到记录 `/admin/attendance`
- **操作**：按日期查看全员签到情况。
- **讲点**：签到记录与人脸打卡事件一一对应，可追溯。

## 5. 现场故障应急

| 现象 | 快速判断 | 处理 |
| --- | --- | --- |
| 页面打不开 / 白屏 | 终端是否还在跑 | 重新 `npm run demo:start`；确认端口 3000 未被占用 |
| 登录后立刻跳回登录页 | Cookie 域名不一致 | 统一用 `127.0.0.1`，不要混用 `localhost` |
| 组卷提示「没有可选题目」 | 题库是否为空 | `npx tsx scripts/demo/prepare-exam-bank.ts` 重建题库 |
| 讨论 / 消息显示「不可用」 | 总开关未开 | 确认 `.env.local` 中 `DISCUSSION_RELEASE_READY="true"` 并重启 dev |
| 人脸打卡失败 | 服务未启动 | `npm run face:start`，再用 `npm run face:status` 确认 |
| AI 助手回答很保守 | 证据模式（预期行为） | 就按「可溯源、不编造」讲，不要现场改开关 |
| AI 接口报错 / 超时 | 网络或额度 | 先展示已有解析结果，跳过需要新调用的步骤 |
| 发布试卷报「字段格式无效」 | 多半是题量或版本不匹配 | 重新预览后再确认；题量不足时勾选「接受减量」 |

**一键自检**：`npx tsx scripts/demo/e2e-walkthrough.ts`（读链路 + 所有页面，约 1 分钟），出问题会明确列出失败项。

## 6. 已知边界（答辩时不要过度承诺）

- 人脸登录/打卡依赖本机摄像头与现场光线，**模型健康 ≠ 本人摄像头一定通过**，需现场实拍验证。
- AI 相关功能依赖在线大模型与额度，现场网络异常时会失败；已解析的内容不受影响。
- 生产部署、公网访问、高并发压测不在本次演练范围内。
- Agent 的「证据模式」是刻意设计，未通过忠实性验收前不开放自由作答。

## 7. 附录：演练脚本用法

在项目根目录执行（需先启动应用）。也可以用两条快捷命令：

```bash
npm run demo:prepare      # 准备演示账号，会真实修改账号数据
npm run demo:walkthrough  # 只读入口与页面可访问性检查；输出本机报告，不改业务数据库
```

单独执行：

```bash
npx tsx scripts/demo/e2e-walkthrough.ts   # 全站读链路 + 全部页面可访问性
npx tsx scripts/demo/e2e-actions.ts       # 有副作用；仅限一次性隔离数据库，结束后需销毁隔离库
npx tsx scripts/demo/prepare-demo-account.ts # 重建演示账号（幂等）
npx tsx scripts/demo/mint-token.ts <email>   # 签发一个调试用 token（排障用）
```

脚本约定：
- 依赖大模型的步骤失败记为「软失败」，不判定为代码缺陷。
- `e2e-actions.ts` 会在学习者/管理员数据中创建笔记、复习记录、练习、出勤、讨论和账号，且没有自动清理；不要因使用演示账号就直接对共用数据库运行。
- 所有脚本都从 `.env.local` **强制覆盖**读取环境变量：因为 `@prisma/client` 会自动载入根目录 `.env`，而 Next.js 的优先级是 `.env.local > .env`，两者相反，直接用 `process.loadEnvFile` 会导致签发的 JWT 密钥与应用不一致（表现为全部接口 401）。
