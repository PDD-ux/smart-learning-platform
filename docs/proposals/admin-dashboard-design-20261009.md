# 管理员专属总览页设计提案

日期：2026-10-09  
状态：用户于 2026-10-09 确认；已纳入 §16 并完成实现。

## 目标

管理员登录后进入独立的“平台管理中心”，能快速查看账号和签到概况，并进入已有的用户管理、签到记录页面。`/admin`、`/admin/users`、`/admin/attendance` 共用管理员专属布局；管理区域只呈现管理员任务，不继续显示学习者的学习、复习和个人功能导航。学习者登录后仍进入 `/dashboard`。

静态视觉稿：[admin-dashboard.html](../../prototype/admin-dashboard.html)。页面现由 `GET /api/admin/overview` 提供真实统计；原型中的示例值只用于视觉占位。

## 页面结构

- **专用侧栏**：品牌、管理总览、用户管理、签到记录，以及管理员身份标识。三个管理路由共用该侧栏；侧栏不放学习者菜单。
- **顶部栏**：当前位置、管理员身份和退出入口。
- **页面首屏**：标题“平台管理中心”，提供“管理用户”和“查看签到记录”两个主要入口。
- **概况卡片**：账号总数、学习者、管理员、今日签到数；签到卡可拆分自动签到与人工确认。
- **常用管理**：分别进入 `/admin/users` 和 `/admin/attendance`。
- **管理范围提示**：说明页面仅做账号与签到管理，并强调人脸信息和学习内容的访问边界。
- **首屏下方**：最近新增账号（昵称、角色、注册日期）和签到方式汇总，分别链接到已有的管理页。

## 数据与权限边界

新增管理员专用 `GET /api/admin/overview` 聚合账号角色计数、上海时区今日签到计数和最近账号；页面不依赖审计动态接口，避免把示意数字误当成真实数据。不要呈现虚构的“平台动态”或审计事件；当前稿已改为不依赖后端数据的“管理范围”说明。

总览页和聚合接口都必须服务端校验 `role=admin`。学习者访问时返回 403/无权限页面。只读取用户计数、脱敏昵称/角色/注册时间、签到结论/时间统计；不返回账号凭据、学习者笔记或内容、人脸图片、特征向量及相似度分值。接口字段、错误行为和页面交互已同步至 `spec/03-ARCHITECTURE.md`、`spec/04-DATA-MODEL.md` 与 `spec/02-DESIGN.md`。

## 页面状态与适配

- 加载时显示概况卡和列表骨架；不得在数据未加载时把空值显示为真实的 0。
- 无账号或无签到记录时分别展示清晰空状态和对应管理入口。
- 聚合失败时给出可重试的错误提示；403 显示无权限状态。
- 宽屏使用左侧管理导航和两列卡片；窄屏侧栏改为顶部三项导航，概况卡两列排列，内容区单列。
- 颜色、圆角、阴影沿用项目“纸张学习桌 · 彩色贴纸”设计规范；页面对比度和焦点状态遵循现有按钮/链接规范。

## 不在本提案范围

不增加角色类型、教学管理、内容审核、系统监控、权限配置、批量导出或新的审计查询功能。实现范围已由用户确认，并记录在 PRD、页面设计和 `spec/05-TASKS.md` §16。

## 评审验收点

1. 管理员登录后进入 `/admin`；总览及两个现有管理页面共用专属管理员导航，不混入学习者菜单。
2. 四项概况和最近账号都来自真实数据库；空、加载、失败和无权限状态清楚。
3. 普通学习者不能通过直接访问页面或接口看到管理数据；接口回归覆盖匿名、学习者和已被降权的旧管理员令牌。
4. 总览不呈现原始人脸/特征数据、学习者私有学习内容或伪造的平台动态。
5. 桌面和窄屏布局都可操作，键盘焦点清晰。
