# §29.8 智能作业批改、错因与订正报告

## 目标与边界

29.8消费§29.7本人逐题确认并冻结的`HomeworkDraft`。系统对学习者明确选中的题目调用现有Spark Lite网关，生成有界的AI建议、来源依据、错因与下一步提示；本人提交订正后再次核对，并保留初次答案、订正答案及复核结果。

报告只服务原作业所有者。引用的题干、学生答案、参考答案和评分依据都是用户提供内容，不代表外部权威已验证。报告不改写`HomeworkDraft`、`SubmissionVersion`、`AssignmentReview`、班级正式成绩或`Mastery`/`ExerciseRecord`。AI建议、严格可识别的选择/判断规则比对和负责人正式批阅分区显示；不能把AI建议称为教师评分。班级正式批阅仍由既有负责人流程独立写入。

## 调用预算和输入

- 只允许`HomeworkDraft.state=CONFIRMED`的新建报告；仅能选择该快照中已确认、完整、逐题复核的题号。
- 每个报告最多8题，完整输入总计最多16000字符；草稿最多20题，可由本人明确分批处理。禁止截断、拼接其他账号资料或上传新原件来替代冻结快照。
- 模型使用现有Spark服务端网关和当前统一型号；批改说明与JSON题目数据放在单条user消息中，明确题目、答案及评分依据是不可信数据、不能作为指令。单次结构化请求最多进行网关既有2次校验尝试，每次超时45秒、输出不超过3500 token；失败不保存部分题目，不自动启动新一轮。
- 非“待核验”建议必须带有逐字命中本题参考答案或评分依据的短摘录。不能核对的摘录、缺失题号、重复题号、未知字段、不安全输出或题目数量不全均使整份分析失败。
- 客观规则只覆盖可明确规范化的选项标记和中英文判断值；未识别时返回“无法自动比对”。它不使用简答题模糊匹配，也不据此更新掌握度。
- 客观命中与失配分别对应严格规则结果100%/0%；若AI的对错建议或百分比与可执行规则任一不一致，该题降为`needs_review`并清空AI分数，保留规则结果供本人核对。
- AI建议分是0–100百分制：`correct`必须为100，`incorrect`必须为0，`partial`必须为1–99，`needs_review`必须为`null`。结论标签与建议百分比自相矛盾时，也降为`needs_review`并清空分数；不把“1”解释为满分或置信度。

## 生命周期和重放

`PENDING → RUNNING → READY | FAILED | CANCELLED`。报告在模型调用前持久预留，输入快照及摘要与任务同时保存；模型不在数据库事务/行锁内运行。超出租约改为失败，不自动重发。取消会立即禁止结果写回，并尝试中止当前进程的请求；多实例场景即使上游已收到请求，也不得保存迟到结果。

每次报告由用户生成的UUID请求键和完整规范化输入摘要唯一绑定。同键同内容返回原状态/结果，同键异内容冲突；需要重试时必须由用户明确创建新报告。订正以乐观版本号、独立幂等键追加，最多50次；每次保存订正前答案、订正后答案、状态及成功复核结果。失败或取消保留订正草稿，不能覆盖第一次分析或自动重试。

## HTTP契约

- `GET /api/homework/:id/grading`：仅本人读取该校对记录最近20份报告及精简输出。
- `POST /api/homework/:id/grading`：`{requestId, expectedDraftRevision, consent:true, questionNumbers}`，服务端强制同意标记，题号1–8个且唯一；只预留PENDING报告，创建时间留作同意记录。
- `POST /api/homework/:id/grading/:reportId/run`：仅启动PENDING报告；返回持久状态，重放不得重复调用模型。
- `POST /api/homework/:id/grading/:reportId`：严格联合命令`correct`或`cancel`。订正需`requestId / expectedRevision / consent:true / number / answer`，服务端验证显式同意后才调用模型；失败或取消的相同答案可用新键明确重试。取消需`requestId / expectedRevision / target`，target为analysis或correction并对后者指定targetRequestId。
- `GET /api/homework/mistakes`：最多50条未完成的本人作业错因，按最近报告优先，包含原作业与报告ID；仅把AI标为部分/不匹配且尚无成功订正确认的项列入“练习与错题”。它是现有巩固页的来源分组，不把答案伪造成`Exercise`，不更新知识掌握度。

报告及错误都使用private/no-store；请求体严格校验；AI调用按用户限流；错误只存固定白名单代码，不落模型原文、凭据或私有日志。跨用户及无权角色按现有本人作业接口返回不可访问。

## 页面与验收

批改入口嵌入已有`/homework/:id`冻结校对页，用户勾选1–8题并看到模型发送说明后启动；页面分栏/窄屏样式沿用现有作业卡片。报告逐题展示AI建议、建议分、依据摘录、错因、规则比对状态和待核验提示；订正后追加复核记录。所有分数均标为AI建议或规则比对，不显示整体正式成绩，不向负责人提交或自动发布。

在既有`/question-bank`展示独立标注来源的未解决作业错因入口，并提供返回原报告的链接；页面不新建刷题中心。验收使用合成题目验证无丢失/无串号的结构、逐字来源和明显不确定案例；同一账号/跨账号、重复键、并发启动、取消与迟到响应、失败恢复、订正前后快照和既有正式成绩完整性均需检查。真实模型响应与教学语义质量分开记录；短合成样例不能证明广泛学科能力。
